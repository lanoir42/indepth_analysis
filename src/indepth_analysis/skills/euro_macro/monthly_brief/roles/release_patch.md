# release_patch — 발표치 반영(발표 대기 블록 교체)

초안(컨센서스 선반영)의 `<!-- PENDING:<id> -->` 블록을 실제 발표치로 고친다. **블록과 그 판단에 직접 걸린 문장만** 고치고 나머지 본문은 건드리지 않는다.

## 입력
- `IN=` 초안(리포트 또는 해설본), `OUT=` 출력 경로, `_common.md`(7절), `PKG/STYLE_BRIEF.md`
- `data/pending_releases.json`(컨센서스·해석 포인트), `data/pending_actuals.json`(실제치 — Sonnet 확인), `data/facts.md`·`data/table_pack.json`(재빌드된 결정론 값 — 같은 지표가 있으면 **이 값이 우선**, 불일치는 로그에)
- (리포트를 고칠 때) 요약·1장·9장 전망에서 해당 id를 언급한 문장

## 절차
1. id마다 실제치·컨센서스·직전치를 대조해 `상회|하회|부합`(차이 표기: %p 또는 pt)을 판정.
2. 블록을 **확인 서술**로 교체(표지 삭제). 리포트 형식:
   ```markdown
   - **(<지표> 확인, <M/D>)** <실제>(e<컨센서스>, 직전 <값>; <출처>)로 컨센서스를 <n>%p <상회/하회/부합>했음. 발표 전에는 <컨센서스가 의미하던 것>으로 봤는데, 실제치는 <초안의 상회/하회/부합 해석 중 해당 경로>를 가리킴 → <판단이 재확인/강화/수정되는 내용 1~2문장>.
     - <구성 항목·수정치 등 세부(있으면)>
   ```
   해설본 형식: 숫자 풀이 예제에 실제치를 넣어 계산을 완성하고, "예상 대비 실제" 차이를 읽는 법을 1~2문장으로.
3. 결과가 초안의 블록 밖 판단과 **충돌하면**(예: 하회인데 본문이 '추가 인상 불가피') 해당 문장을 실제치에 맞게 고치고 로그에 남긴다. 요약 불릿·1장 판단도 같은 기준으로 점검.
4. 실제치가 아직 없으면(`not_released`) 블록을 유지하고 로그에 남긴다.
5. 금지 토큰 자가 점검(`_common.md` 5절 스크립트) 후 저장.

## 산출
- `OUT` 파일, 로그 `audit/<OUT stem>_release_log.md`(id | 컨센서스 | 실제 | 판정 | 고친 위치 | 블록 밖 수정 여부)
- 마지막 출력: `{"ok": true, "output": "<OUT>", "note": "교체 N·유지 M·블록 밖 수정 K"}`
