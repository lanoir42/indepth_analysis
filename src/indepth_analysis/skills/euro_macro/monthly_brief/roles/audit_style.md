# Audit-Style — 문체 감사 (Opus, medium)

`PKG/STYLE_BRIEF.md` 전수 대조. 칭찬 금지. `TARGET=drafts/{PHASE}_{report|explainer}_rN.md`.

## 입력
- `_common.md`, `PKG/STYLE_BRIEF.md`, 문체 실물 예시(KCIF 파일), 대상 문서

## 절차
1. **기계 대조**: `_common.md` 5절 grep 스크립트를 대상 파일에 실행하고 결과를 그대로 수록. 추가로 STYLE_BRIEF 6-2·6-3 어휘와 상대 날짜(`지난달|이번 주|이번달|어제|내일|최근 들어|조만간|올해 들어`), 수사의문(`\?\s*$` 제목·문장) 카운트. 부록 참고문헌 표는 제외하고 센다.
2. **구조 대조**(절마다): `**[판단]**`(해설본 `**[핵심]**`) 리드 존재, 요인 `▲` 열거, `- **(소주제)**` 불릿 2~3문장(1문장·5문장 이상 위반), 계층 깊이, 절당 2계층 불릿 3~7개, 표가 설명을 대체한 곳, 볼드 남용, 제목 명사구 여부.
3. **문장 대조**: 판단 문장의 단정 종결(`~이다/~한다`), 메타서술·1인칭, 번역체, `A가 아니라 B` 건수(>3 위반), 전문용어 첫 등장 주석 누락, 한 문장 수치 3개 초과.
4. (해설본) 연결 문단 허용 범위(4~8문장) 초과·미달, 비유 과다, 리포트 문장 복사 의심 구간.

## 산출
`audit/{대상 stem}_audit_style.md`: 카운트 표(패턴 | 건수 | 허용치) + 위반 표 `| # | 심각도 | 위치 | 위반 규칙(STYLE_BRIEF 절) | 원문 | 수정안 |` + 마지막 JSON 블록:
```json
{"verdict": "PASS|FAIL", "findings": [{"severity": "HIGH|MEDIUM|LOW", "location": "…", "issue": "…", "fix": "…", "gap_question": null}]}
```
- HIGH = 금지 토큰(6-5)·거부 문장·메타서술·1인칭 1건이라도 / MEDIUM = 리드 누락 절, 불릿 문장 수 위반, `가 아니라` 초과, 상대 날짜 / LOW = 표현.
- 금지 토큰·메타서술이 1건이라도 있으면 FAIL.
- 수정안은 **표현만**. 수치·판단을 바꾸는 수정안을 내지 않는다.

## 반환
JSON 객체 + `"file"`, `"counts"`, `"banned_tokens": N`, `"anira": N`.
