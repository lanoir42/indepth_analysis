# 2026-09-29 회고 — 독자가 배울 수 없는 ‘최종 연구 패키지’

## 사용자 피드백과 책임

사용자는 frontier_ai_security_2026_09_28 보고서에 부정형·작업 메타서술·링크가 많고 실질 설명이 부족하다고 지적했다. 목적은 IT 경영진에게 기술·산업·투자 의견을 설명할 수 있도록 공부하는 것인데, 출처를 따라가야 배울 수 있는 조사 메모를 최종본으로 전달했다. 82,900자·62출처·형식 검사 통과를 내용의 완결성 근거처럼 제시한 완료 판단이 잘못됐다.

## 원인

1. 사실을 과장하지 않는 것에 집중하면서 사실·기술·논증을 충분히 설명하는 작업을 뒤로 미뤘다.
2. 조사되지 않은 부분을 ‘확인하지 않았다’고 밝힌 뒤 완료로 처리했다. 공개 자료의 불확실성과 집필자의 조사 부족을 혼동했다.
3. 실제 분석 대신 분석 방법·향후 확인할 질문을 적었다. 결과와 계획을 분리하지 않았다.
4. 링크·표·출처ID·문자수·lint를 독자의 이해도 검증으로 잘못 대체했다.
5. 기존 Claude feedback_prose_report_format.md에 이미 ‘메타서술 금지·독립 본문·A가 아니라 B 남용 금지’가 있었는데 실행하지 못했다. 새 규칙의 부재보다 기존 규칙 준수와 내용 검토의 실패다.

## 영속 집필 기준 — Claude/Codex 공통

- 독자는 처음 접하는 주제라도 본문만으로 핵심 사건의 과정, 기술의 작동, 논쟁의 근거, 경영·투자 전달경로를 설명할 수 있어야 한다.
- 각 장의 리드는 실제 질문에 대한 답을 제시한다. ‘무엇을 구분해야 하는가’만으로 장을 끝내지 않는다.
- 주장에는 그 주장을 이해할 배경, 구체적 사례/관측, 작동 원리, 그로부터 결론이 나오는 이유를 연결한다. 용어를 다른 전문용어로만 풀이하지 않는다.
- 외부 링크는 근거다. 설명 자체를 외부 링크에 위임하지 않는다. 원문의 요약/도입만 열람했으면 논증 전체를 검토한 것처럼 쓰지 않는다.
- ‘하지 않는다/아니다’는 필요한 구분에만 사용한다. 독자가 물을 ‘그래서 실제로 무엇인가/왜 그런가/어떻게 작동하나’에 답한다. 기계적 부정어 삭제가 목표가 아니다.
- 불확실성은 해당 결론에 미치는 영향과 함께 설명한다. 조사 부족이면 추가 조사하며, 미공개 자료이면 대체 근거·추정 범위·결정 영향까지 제시한다.
- 검증 절차·작업 내역·읽지 못한 자료 목록은 docs/research의 편집/검증 기록으로 분리한다. 독자용 본문에 집필자의 자기보고를 반복하지 않는다.
- 내용 검수: 링크를 가리고 읽었을 때 사건 경로·기술 원리·논쟁의 양쪽 논증·기업별 수익화 경로·시나리오별 행동을 설명할 수 있는지 구체적으로 확인한다. 자동 검사 PASS는 이 검수를 대체하지 않는다.
- 분량/출처수는 부록 통계다. 길다고 완성본이 아니며 짧다고 개선본도 아니다. 핵심 질문의 답과 구체 설명을 대조해 완료 판단한다.
- 본문은 중요도 있는 설명 단위로 쓴다. 기존 가독성 우선 개조식 선호를 유지하되 긴 기술 해설은 연결된 문단을 활용한다. 표는 실제 비교에만 쓴다.
