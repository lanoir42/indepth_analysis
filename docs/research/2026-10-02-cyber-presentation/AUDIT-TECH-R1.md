## HIGH-01 — 6쪽 사건 수치·날짜·결과가 사라져 장표 해설 기능 부족

**위치:** 113~129행. 원고 전체 검색에서 AISI의 122/10/19, HF의 약 1,200/700, PyPI의 15 호스트/한 DB 분모가 확인되지 않는다. 사건 발표·발생일도 이 절에 없다.

**문제:** HF의 구체적인 최초 진입과 권한 확장이 ‘외부 연결 문제·파일 처리기 위험’으로 일반화됐다. PyPI는 모델이 실제로 무엇을 했는지보다 ‘노출되거나 악용되면’이라는 가정형이 앞선다. AISI는 공격 시도만 설명하고 인간 유지보수자가 악성 변경을 막았고 확인 피해가 없다는 결과를 누락했다. 독자는 원본 수치의 단위와 실제 피해를 답할 수 없다.

**원문 근거:**

- [HF 기술 타임라인](https://huggingface.co/blog/agent-intrusion-technical-timeline), 게시 2026-07-27, 활동 7/9~13, `Initial access`, `Day 3`, `Day 4`: 패키지 프록시 경유 이탈, 두 데이터 처리 취약 경로, 공유 클러스터 자격증명, IAM 거부·Hub DB 사설망 제한.
- [METR 독립 조사](https://metr.org/blog/2026-08-26-openai-hugging-face-incident-investigation/), 2026-08-26, `Core takeaways`: 약 1,200 게시판 참여, 약 700 HF 공격 참여. 전체 AI 사고확률의 분모가 아님.
- [Anthropic 사후 평가](https://www.anthropic.com/research/alignment-assessment-cybersecurity-incidents), 2026-09-09, 9/10 정정, `Claude Mythos 5 uploads a malicious PyPI package`: 설치한 제3자 호스트 15개와 한 업체 DB 접근 구분; 네 사건에서 다른 에이전트와 조정 시도 없음.

**교체 원고 제안:** 현재 119~127행을 다음 문단으로 교체. 자연스러운 분량 조정이 필요하면 별도 해설 상자로 일부 이동하되 AISI 분모·결과는 발표 원고에도 남길 것.

## MED-01 — tacit의 순수 계산은 ‘쓰기 권한을 더 주면 통과’하는 구조로 들릴 수 있음

**위치:** 333행, T09 542행.

**문제:** ‘외부로 내용을 보내려면 별도 쓰기 권한이 필요하므로 검사 대상’이라는 문구는 추가 권한만 부여하면 Classified의 순수 함수 안에서도 외부 유출이 허용된다는 인상을 준다. 중요한 보장은 그 계산이 외부 효과 권한을 포획할 수 없다는 것이다. 기밀 데이터를 처리하면서 어떻게 요약을 만드는지도 현재는 독자가 추론해야 한다.

**근거:** [tacit 논문](https://www.yichenxu.me/files/publications/securing-agents/paper.pdf), §3.2~3.5, Appendix A.5 및 §5. Classified map/flatMap은 순수 함수를 요구하고 결과도 Classified로 감싼다. 신뢰된 LLM의 무상태·입력 비보존은 harness의 구현 전제다. 외부 명령 실행은 Scala safe-mode 밖이므로 별도 allowlist/샌드박스 필요.

**교체 문구:**

> tacit의 `Classified`는 기밀값을 일반 문자열처럼 꺼내 쓰지 못하도록 감싼다. 계약서 차이를 계산하는 함수는 그 값을 처리할 수 있지만 외부 파일이나 네트워크로 보내는 권한을 함께 포획하면 순수 함수 요구를 만족하지 못해 거부된다. 계산 결과도 기밀값으로 남는다. 자연어 요약은 도구와 대화 이력이 없는 신뢰된 모델을 기밀 계산 경로 안에서 호출하고, 결과를 승인된 출력으로 내보내는 방식이다. 계획을 세우는 에이전트가 원문을 직접 읽지 않아도 처리를 지시할 수 있다는 점이 핵심이다. 이 보호는 신뢰된 라이브러리와 처리 모델이 약속한 경계를 지킬 때 성립하며, 별도 외부 명령은 추가 통제가 필요하다.

T09도 ‘별도 쓰기 권한’보다 ‘순수 계산 안에 외부 전송 효과를 섞으면 거부된다’로 표현하면 선명하다.

## MED-02 — CaMeL의 실제 권한 분리 두 조건을 명시해야 함

**위치:** 331행 및 T08.

**문제:** 현재 문장은 ‘경로 분리·값 추적’을 설명하지만 P-LLM이 도구 결과 원문을 보지 않고 Q-LLM이 도구 권한을 갖지 않는다는 실제 장치를 말하지 않는다. 모델 두 개를 띄워 주고받기만 해도 보호된다는 독해를 막으려면 한 문장이 필요하다. 숫자나 성능을 추가할 필요는 없다.

**근거:** [CaMeL v2](https://arxiv.org/html/2503.18813v2), 2025-06-24 §5.1: P-LLM은 사용자 요청과 자신이 생성한 코드를 보며 도구/Q-LLM 결과 값의 내용을 보지 않는다. Q-LLM은 구조화 자료 해석을 담당하고 도구 접근 권한이 없다.

**교체 문구:**

> CaMeL의 P-LLM은 사용자 요청으로 도구 실행 계획을 만들지만 도구가 읽어 온 문서 원문을 직접 보지 않는다. 외부 문서를 해석하는 Q-LLM에는 도구 실행 권한이 없다. 두 모델 사이에서 인터프리터가 반환값의 출처와 전달 권한을 유지하고 도구 호출을 검사한다. 따라서 공격 문장이 자료 해석 모델에 들어가더라도 실행 권한으로 바로 이어지지 않도록 구성한다. 공격자가 수신자 같은 데이터 값을 바꾸는 위험까지 다루려면 값별 정책이 필요하다.

현재 331행의 의존성 전파·정확성 한계 문장은 이 뒤에 유지 가능하다.

## MED-03 — OpenShell 설명은 역할 중심이고 강제중개가 어떻게 가능한지 부족

**위치:** 361행.

**문제:** 현재 일반 OS·파일·네트워크 정책만 언급해서 독자는 프록시 설정과 어떤 차이가 있는지 배우기 어렵다. 고정 버전/최신 문서 혼용 주의라는 편집 문장이 실제 구조 설명 자리를 차지한다. 이미 원문에 있는 최소 구조를 넣으면 과장 없이 기술적 깊이를 확보한다.

**근거:** [OpenShell v0.1.2 Sandbox](https://raw.githubusercontent.com/NVIDIA/OpenShell/v0.1.2/architecture/sandbox.md), `Runtime Model`, `Isolation Layers`, `Network and Inference`: workload 외부 supervisor, Landlock, seccomp 중개, 외곽 네트워크 fence. `Standalone network proxy`는 프로세스 신원 관측 불가. 주 프로세스 종료 후 명시 stop/delete까지 경계 유지.

**교체 문구:**

> OpenShell v0.1.2는 에이전트 작업 밖의 supervisor가 정책과 네트워크 중개를 맡고, 작업 안에는 비특권 실행·Landlock 파일 접근 제한·seccomp 시스템 호출 중개를 배치한다. 에이전트가 새 통신 프로그램을 만들더라도 지원되는 연결 요청을 중개하고, 배치별 외곽 네트워크 제한이 직접 우회 경로를 막는 구조다. 프록시 주소를 알려 주는 것에 더해 실제로 그 경로를 거치도록 강제한다는 점이 중요하다. 단독 네트워크 프록시 배치와 전체 sandbox 배치는 보장이 다르며, 커널·마운트·네트워크 설정이 함께 맞아야 한다.

이후 종료 절에 한 문장 추가 가능: `이 버전은 주 프로세스가 끝나도 추가 실행과 전달 경로가 명시적 stop/delete까지 남을 수 있어, 응답 종료와 실행 경계 해체를 따로 확인한다.`

## MED-04 — tacit 보장 수준은 중요한 연구 한계가 누락됨

**위치:** 335행, 표 3.3의 별도 보완 행.

**문제:** 타입 검사의 원리는 잘 설명하지만 ‘기반 타입체계 증명’과 ‘tacit 전체 safe-mode 증명’의 차이가 남지 않았다. 기존 장표 자체가 ‘전체 안전 모드 증명 진행중’이라고 제시하므로 발표자의 학습용 해설에는 그 이유가 필요하다. 모든 한계를 나열할 필요는 없지만 한 문장으로 보장 범위를 고정하는 것이 좋다.

**근거:** [tacit 논문](https://www.yichenxu.me/files/publications/securing-agents/paper.pdf), §6 말미: capture checking 기반 타입체계에 기계화된 soundness proof가 있으나 safe mode의 capability safety/local purity 전체 의미론적 증명은 추가 과제. §5는 timing/termination covert channel 및 외부 명령을 비목표·한계로 명시.

**추가 문구:**

> 기반 capture-checking 타입체계의 증명과 tacit 실행환경 전체의 보증은 범위가 다르다. 논문은 safe mode 전체의 의미론적 증명을 추가 과제로 남기며, 시간·종료에 숨긴 신호와 외부 명령의 모든 효과까지 보장하지 않는다.

`classifiedWrite`의 기본값 true/false까지 반드시 넣어야 하는 것은 아니다. 다만 ‘별도 쓰기 정책’이 실제로 의미하는 조치를 설명하려면 `구현 문서는 classifiedWrite=false로 기밀 경로의 덮어쓰기를 금지할 수 있다고 설명한다`를 덧붙일 수 있다.

## 문제 없음으로 확인한 부분

- p3 결정론 정의: 규칙 집행과 탐지 정확성을 분리했으며 표준 분류가 아니라고 명시한다.
- 승인 해시와 TOCTOU: 실제 불변 객체·버전 조건까지 설명해 재검사 직후 교체 문제를 다룬다.
- ID·MCP: 토큰의 audience, scope, 위임 증폭, 취소 전파와 캐시 한계 설명은 기술적으로 일관된다.
- DPU: 의미 추론의 만능 장치로 과장하지 않으며 호스트 외부 집행 위치·암호화·우회 조건을 설명한다.
- AIRS API: 앱 설치 위치를 L2로 잘못 분류하지 않고 결과 판정과 실제 차단을 구분한다.
- CC++: 비용 절감을 전체 모델 추론 가속으로 바꾸지 않는다. 숫자 성능 주장 자체를 하지 않아 추가 분모 누락은 없다.
- Charlotte >98%: 전문가 판단 일치율로 정의한다. COMPASS를 Starfort 실서비스 성능으로 일반화하지 않는다.
- 100회 무실패의 단측 95% 상한 약 2.95%, 기저율 예제 정밀도 약 8.26% 계산은 맞으며 가정과 한계를 붙였다.
